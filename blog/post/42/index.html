2026 版的核心变化

2026 年 8 月，OWASP 发布《Top 10 for LLM Applications 2026》。本版首次用「证据」校准「共识」——将社区投票与 7,714 起真实安全事件比对，榜单由「社区投票（占 3/4 权重）+ 真实事件数据（占 1/4 权重）」共同决定。

项目负责人的核心判断：别再试图造一个无法被欺骗的模型，而要围绕模型搭建系统，让它在被欺骗的那一天——而它一定会被欺骗——关键的东西也不会崩坏。

值得关注的「信念 vs 证据」落差：

  • 提示注入守榜首：投票第一，但按真实事件数跌出前十——「防御效应」导致公开计数低估风险。
  • 过度代理权升至第 3：影响最大的位移，投票与记录都认同 agentic 部署是损害落地的关键。
  • 无界消耗上升 4 位：资源与成本耗尽被从业者看得更重。
  • 不当输出处理跌至第 10：跌幅最大，从第五跌到第十。
  • 敏感信息泄露稳居第 2：顶部唯一信念与证据一致之处，也是 OWASP 信心最高的位置。
  • 隐藏上下文暴露为新增项：由「系统提示词泄漏」扩展为更宽的框架。

十大风险详解

LLM01 提示注入 Prompt Injection

根因：LLM 在架构上不区分「指令」与「数据」——二者都是同一条 token 流，不存在参数化查询那样干净的等价物。输入不必人类可读、不必来自用户、也不必在界面可见，就能改变模型行为。

典型危害

  • 间接注入：网页、邮件、RAG 段落里藏指令，模型读取即执行（如 EmailGPT）。
  • 零点击外传：一封构造邮件让 M365 Copilot 无需交互即外传组织数据（Aim Security, 2025）。
  • 多模态隐写：图像中亚感知扰动被视觉编码器提取，在肿瘤影像 VLM 上演示过。
  • 经由 MCP：投毒 GitHub issue 外传私有代码库（Invariant Labs, 2025）；恶意 postmark-mcp 跨约 300 家组织密送邮件。
  • 「致命三角」：能同时访问私密数据 + 摄入不可信内容 + 对外通信的代理，具备高影响利用条件，去掉任一条腿即可消除（Simon Willison, 2025）。

防御要点

  • 架构性防御而非拦截式——假设指令边界终将被绕过，约束模型被允许做什么、输出能触达何处。
  • 凭据与改状态能力放应用代码里，对每个操作授最小权限，经确定性策略引擎复核。
  • 高影响/不可逆动作前显式人工确认；用「二选一规则」为代理能力做预算。
  • 记忆写入当特权操作；MCP 服务器 pin / 签名 / 校验；针对自适应攻击者做 red team。

LLM02 敏感信息泄露 Sensitive Information Disclosure

泄露面：远不止最终答案——工具调用参数、推理轨迹、检索块、多模态输出、日志、遥测、embedding，乃至可观测推理属性（时序、token 长度、对数概率、置信度、缓存命中）都是泄露通道。分训练期 / 推理期 / 流水线期 / 观测期四个阶段。

典型危害

  • 「诗」发散攻击让 gpt-3.5-turbo 以约 200 美元输出 1 万+ 被记忆样本（Nasr et al., 2023）。
  • ChatGPT Redis 漏洞暴露 1.2% Plus 订阅者支付 PII；4500+ 共享对话因缺 noindex 被 Google 索引。
  • 2025 年 DeepSeek ClickHouse 暴露超 100 万行日志与 API 密钥；Check Point 2026 披露 ChatGPT 经代码运行时静默 DNS 外传通道。

防御要点

  • 检索前授权：在索引查询内强制文档级/块级 ACL，而非检索后再过滤。
  • 系统提示词卫生——绝不放密钥；用分类器而非正则清洗（正则败给编码与跨语言）。
  • 把推理轨迹当一等输出脱敏；侧信道防御用流式随机填充与 token 批处理。
  • 高级场景：DP-SGD、向量库隔离、机密计算、可验证擦除、把泄露 red team 作为发布门禁。

LLM03 过度代理权 Excessive Agency

根因：通常为三者之一或多个——过度的功能（给了不需要的工具能力）、过度的权限（对下游系统权限过大）、过度的自主性（高影响动作无独立校验）。

典型危害

  • 邮件助手本只需「读邮件」，工具却含「发信」功能，叠加间接提示注入 → 转发收件箱敏感信息。
  • 2025 年 7 月 Amazon Q VS Code 扩展：破坏性系统提示词被提交；另一运行时注入使 Amazon Q 执行任意代码。

防御要点

  • 最小化工具 / 功能 / 权限：避免「运行 shell」「抓取 URL」等开放式工具，改细粒度专用工具。
  • 在用户上下文中以最低权限执行；用 OAuth 最小作用域认证。
  • 完全中介：授权在确定性策略引擎中强制执行，而非依赖 LLM 决定。渐进式执行（审计 → 告警 → 阻断 → 升级），可挽回动作自动批准，不可逆动作路由人工。
  • 监控工具使用 + 速率限制 + 熔断器。

LLM04 供应链 Supply Chain

风险面：第三方预训练模型、数据集、LoRA 适配器等可复用制品，可经篡改、投毒或恶意替换被操纵。今年还纳入「所推广的模型制品名不副实」这种信任失败。

典型危害

  • PyTorch 供应链攻击（torchtriton, 2022）；Ollama CVE-2024-37032 经恶意模型清单 RCE；llama.cpp GGUF 堆溢出 CVE-2024-23496。
  • PoisonGPT：外科手术式改参数，传播错误信息却躲过标准基准检测。
  • 模型命名空间复用：原作者删号释放命名空间，攻击者重注册同名发布恶意模型 → 远程代码执行。
  • 扫描器与安全加载器被绕过（PickleScan zero-day、torch.load weights_only CVE-2025-32434）；Ultralytics 经 GitHub Actions 缓存注入木马。

防御要点

  • 审查数据源/供应方/T&C；应用 A06:2021 的漏洞扫描与打补丁。
  • 维护扩展到模型/适配器/数据集的 SBOM（AIBOM / ML SBOM）。
  • 只用可验证来源模型 + 签名（Sigstore / OpenSSF）+ pin + 来源策略 + SLSA 发布门禁。
  • 把模型转换/合并服务视为高风险提升点；边缘部署加密 + 厂商证明。

LLM05 数据与模型投毒 Data and Model Poisoning

关键：投毒针对模型的「学习过程」而非单一运行时缺陷。发生在数据被摄入/变换/检索/复用的任何地方——预训练、fine-tuning、embedding、RAG、模型分发。修复往往要重训或换模型，昂贵且 disruptive。

典型危害

  • 仅 250 份投毒文档即可攻陷 600M–13B 参数模型（Souly et al., 2025）。
  • RAG 知识库投毒：改写/检测防御下仍保持高成功率（Zhang et al., 2025）。
  • 修改聊天模板触发：18 个模型、4 个运行时验证，触发条件下事实准确率 90% → 15%，URL 发射成功率 >80%（Fogel et al., 2026）。
  • 恶意内部人员向训练集注入错误标注交易数据 → 欺诈检测失效；医疗模型最小投毒显著改变安全攸关建议。

防御要点

  • 用 SBOM/ML-BOM 跟踪谱系 + 签名校验，跨生命周期持续校验数据完整性。
  • 保护 RAG：强制信任边界、过滤检索内容、来源评分、系统指令与外部数据隔离。
  • 沙箱隔离；统计/AI 异常检测监控训练损失与行为漂移。
  • 每个对齐周期后都做触发器探测——别假设安全对齐能移除后门；推理制品当安全相关代码（签名/hash/diff/静态分析）。

LLM06 无界消耗 Unbounded Consumption

定义性特征：成本不对称——攻击者以对自身可忽略的代价，触发代价高昂的计算。仅靠传统「每秒请求数」速率限制已不够，需要 token 感知的成本控制。

典型危害

  • 钱包拒服务（DoW）：利用按使用计费模型制造不可承受财务负担。
  • 推理回路攻击：短小良性提示迫使 extended-thinking 模型进入不终止推理，耗尽 thinking token。
  • 智能体会话不断累积上下文：首轮约 $0.001 → 第 100 轮约 $0.50，单看都不超限，聚合却达数百美元。
  • 恶意工具诱导代理进入递归/无限工具调用循环；模型提取与蒸馏窃取知识产权。

防御要点

  • 硬性支出上限：按 API 密钥/用户/团队/云账户设不可覆盖预算，超出即停推理（不是告警）。
  • 速率限制扩展到「每分钟 token / 每天 token / 每请求估计成本」，预推理 token 估算拒收。
  • 智能体熔断器：步数/递归深度/时间/单次成本上限 + 状态哈希检测循环。
  • 扫描对抗扰动；检测资源密集工具交互；推理基础设施加固（禁不安全反序列化、限特殊 token、强认证）。

LLM07 错误信息 Misinformation

核心风险：错误的输出被信任并据此行动。在现代系统里，模型输出驱动工具调用、生成代码、推断状态、授权动作。错误信息是系统级失败，在智能体中常表现为被下游消费的错误状态/推理/证据。

典型危害

  • 虚构依赖推荐：编程助手推荐看似合理却不存在的包，攻击者预注册（slopsquatting）→ 开发者装了攻击者代码。
  • 客服代理误读策略，批准违反条款的退款；临床摘要遗漏药物禁忌症。
  • 安全代理把正常流量误分类为入侵，自动封锁生产网段致停机。
  • 跨代理信任失败：检索代理谎报「客户已认证」，下游支付代理释放资金。
  • 代理谎报「每晚备份已完成」，实际从未运行 → 恢复失败。

防御要点

  • claim-check-act：生成与执行分离，行动前核验主张，要求输出以权威当前来源 grounding。
  • 校验工具调用（参数/授权/前置条件/当前状态）；用 groundedness 与一致性检查，非仅置信度。
  • 高影响动作运行时校验（审批 + 系统检查）；结构化输出强制必填字段以检测遗漏。
  • 限制爆炸半径（最小权限/沙箱/速率限制）；校准人类与系统的信任。

LLM08 隐藏上下文暴露 Hidden Context Exposure

设计假设：隐藏上下文是「可被发现的」，且其中任何内容都不应被视为机密。系统提示词、工具 schema、RAG 策略文本、工作流判据等非用户可见内容，若含密钥/逻辑即具安全意义。严重程度从「信息性」到「严重（披露链到 RCE）」。

典型危害

  • 系统提示词含凭据 → 泄漏后被挪用。
  • 经对话探测提取工具列表与参数 schema → 为后续提示注入提供具体侦察目标。
  • 提取系统提示词中的拒绝规则 → 精心构造输入绕过 guardrail。

防御要点

  • 不要把敏感数据放进隐藏上下文——凭据/密钥外置到模型不直接访问的系统。
  • 用确定性方法 + 外部 guardrail 做校验与行为控制，不依赖 LLM 内部指令。
  • 授权与访问控制独立 LLM 强制执行（权限分离、边界检查确定性可审计）。

LLM09 向量与嵌入弱点 Vector and Embedding Weaknesses

利用方式：利用 embedding 空间几何与相似度机制，而非模型指令遵循。框架：投毒让系统出错、反演让它泄漏、干扰让它沉默、访问控制失败让它不分彼此。RAG、向量记忆、语义缓存都在此列。

典型危害

  • 跨租户泄漏：相似度搜索在访问控制前跨完整索引运行，可推断其他租户文档存在/主题（CVE-2025-64513 Milvus、CVE-2025-69286 RAGFlow，均 CVSS 9.3）。
  • 嵌入反演：Vec2Text 对 32-token 短输入 92% 精确重建；「仅 embedding」备份 = 源文档泄漏。
  • 检索期数据投毒、阻断器文档使 RAG 下线、成员推断作预言机、语义缓存/去重投毒（跨 AWS/Azure/Alibaba 演示）、单张图像 VD-RAG 投毒。

防御要点

  • 检索前授权：在索引查询内强制租户作用域（非检索后过滤），端点认证 + 按租户速率限制 + 块级 ACL。
  • 按信任层级做索引级隔离（胜过共享索引分类标签）；摄入前规范化（剥离零宽/同形字）。
  • 不向客户端返回原始相似度分数；异常检测 + 交叉编码器重排序。
  • 源文档删除时限期删 embedding；备份同敏感度对待；轮换模型重 embed 全语料。

LLM10 不当输出处理 Improper Output Handling

关注点：LLM 输出在传递到下游组件前缺乏充分校验/清洗。因输出可由提示控制，这类似给用户间接提供对额外功能的访问。成功利用 → XSS / CSRF / SSRF / 提权 / RCE。今年还覆盖编程助手大规模生成的不安全代码。

典型危害

  • LLM 输出直入 shell / eval → 远程代码执行。
  • 生成 JavaScript / Markdown → 浏览器 XSS；生成 SQL 未参数化 → SQL 注入；构造文件路径 → 路径遍历。
  • 聊天 UI 自动渲染 Markdown 图像 → 经图像 URL 外传对话数据（Rehberger, 2024）。
  • 自动编译部署 LLM 生成代码 → 不安全代码进生产。

防御要点

  • 把模型当任何其他用户（零信任）：响应到后端前施输入校验，遵循 OWASP ASVS。
  • 上下文相关输出编码（HTML / JavaScript）；数据库操作参数化/预编译；严格 CSP。
  • 清洗控制字符（ANSI / BEL / OSC / 退格）；日志监控异常模式。
  • 客户端渲染器默认禁用 Markdown 图像/链接预览/iframe 自动渲染，必须渲染则限来源允许列表或服务端抓取代理。

给开发者的防御总纲

为「模型终有一天被用来对付你」而构建：

  1. 假设会被骗：不追求「无法被欺骗的模型」，而是围绕模型搭系统，让一次成功注入不会变成一次成功利用。
  2. 最小权限 + 确定性中介：凭据与改状态能力放应用代码，授权由策略引擎强制执行，而非 LLM 决定。
  3. 人在回路：高影响/不可逆/对外可见动作前显式人工确认，呈现精确渲染动作而非摘要。
  4. 检索前授权 + 索引级隔离：敏感数据在查询内分级，而非检索后过滤；「仅 embedding」备份按源文档泄漏对待。
  5. token 感知成本上限：硬性支出上限 + 智能体熔断器，成本不对称是 LLM 特有风险。
  6. 供应链可验证：模型/适配器/数据集签名、pin、SBOM，把转换合并服务当高风险提升点。
  7. claim-check-act & grounding：错误输出比想象更常被信任并据以行动，先把主张与权威来源对齐再执行。
  8. 针对自适应攻击者 red team：拒绝任何只做静态测试的攻击成功率声明。
